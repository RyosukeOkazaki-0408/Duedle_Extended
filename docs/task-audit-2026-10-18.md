# 課題取得・保存・表示の監査（2026-10-18）

必要な課題の確認を省略しないことを、高速化より優先する。通常更新、自動更新、別タブ取得、直接閲覧、アカウント切替、保存と表示の接続を対象とした。実サーバーへの追加リクエストは行っていない。

## 再現・修正した問題

1. 完全なAPI一覧に含まれない課題でも、別経路から保存できた。APIによる完全な一覧と部分的なHTML観測を区別し、完全な一覧の更新では古い観測を置換する。HTMLの部分的な一覧だけでは未掲載を非表示と判断しない。
2. 最新の取得結果が「不明」でも、以前の「完了」を表示用に保持すると差分取得が再確認を省略した。表示状態とは別に再確認の必要性を保持し、判定できる結果が得られるまで詳細取得を続ける。
3. 通常ページが利用不可から利用可能への変化を先に保存すると、差分取得が再開後の詳細確認を省略した。利用再開を観測した際は古い差分確認基準を無効化する。
4. 未参照・未知の状態や無効な取得日時でも、省略条件を満たせた。既知の状態と有効な取得日時を持つ場合だけ省略を許す。
5. 上記1の対策によって、古い完全一覧にない新規課題まで自動更新で除外されないよう追加検証した。新規・変更されたカレンダー項目が一覧と矛盾する場合、既存のコース探索枠で再確認する。新しい利用可能な課題は取得し、確認できない活動をカレンダーだけで有効にしない。

それぞれ修正前に失敗する回帰テストを確認した。既存の保存済み課題・ユーザー設定は一括削除していない。並列数、クールダウン、通常の起動・提出構成は変更していない。

## 検証

- `scripts/check_extension.py`：JavaScriptCoreで通常取得65件、自動取得23件、更新調整27件、自動制御19件、およびアカウント・別タブ取得・一覧状態・パッケージ検査に合格。
- Chromeの模擬Moodle：実拡張機能の通常更新・差分更新・アカウント切替、利用可否、アクセス拒否、小テスト解析、イベント識別、更新結果表示の6スイートに合格。
- 新規課題、利用再開、不明、開始・期限の変化、更新APIの警告・不正応答・通信失敗を詳細確認の省略条件と併せて検証。部分失敗では差分基準を進めない。
- Safari用リソースを既存プロジェクトに反映し、署名なしDebugビルドに成功。

## 検証の限界

大学側での公開設定変更、提出差戻し、採点変更を実アカウントで操作する試験は未実施。Safari実機のログイン済み環境における再確認も未実施。模擬応答の検証を、大学固有の全設定での動作保証とは扱わない。

通信に失敗した新規課題の詳細や、Moodle自体が返さない課題まで表示を保証するものではない。自動更新は既存の件数・時間制限を維持するため、複数コースの再確認は後続バッチに回る場合がある。ユーザーの非表示設定や表示フィルターも維持する。
