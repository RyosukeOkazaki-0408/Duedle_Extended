# 今回の開発範囲と確認状況

2026年10月11日の追加指示により、通知機能はChrome・Safariとも提供しない。iOS風モードと一般利用者向けガイド・報告フォームは今回の範囲外とする。元の開発仕様書第8・9節に優先する。

## 実装

- ChromeのOS通知の配信・クリック処理・定期アラーム登録を削除。manifestから `notifications` と `alarms` を削除。古い通知済みフラグは課題保存時に取り除く。
- 新規導入時のテーマ初期値はライト。更新時に設定未保存だった既存環境は従来の端末同期を維持。明示的な選択はどちらでも優先する。
- 課題メニューは未設定ならON、明示的なOFFは再読込・別タブでも維持。初期保存と表示の競合を解消。
- 未取得、取得中、正常取得0件、フィルター0件、取得失敗・ログイン切れを区別。既存の課題は更新中も表示する。
- `refreshHistory.fullSweepAt` と `calendarAt` で課題更新と締切一覧確認の成功時刻を区別。対象範囲の取得と必要な保存が完了した時だけ進める。詳細の `fetchedAt`、部分ページの取得、表示操作とは独立する。
- 取得・保存の本番クラス、スケジューラー、課題一覧UIを呼ぶオフラインの開発用拡張を追加。[使い方](debug.md)
- Chrome側にもSafari側の共有ソースと検証用スクリプトを反映。通常のChrome読込先は `src/`。

## 検証範囲

`python3 scripts/check_extension.py` はJavaScript構文、manifest参照、保存競合、収集・表示、長押し並べ替え、プレビュー、自動更新、設定移行、空状態・更新時刻を検証する。

追加のブラウザテスト `tests/browser-debug.cjs` は、開発用拡張を一時Chromeプロファイルに読み込み、初回表示、手動・自動更新、クールダウン、OFF設定の復元・別タブ反映、フィルター、保存失敗、ログイン切れ、正常取得0件、外部HTTP通信がないことを確認する。Playwrightと対応Chromeを別途必要とする。

2026年10月11日、回帰テストと両ブラウザテストは成功。Mac・iOS Simulatorの署名なしビルドも成功。Safari成果物に新しい一覧状態クラスが含まれ、開発用資産が含まれないことを確認した。

`tests/browser-production.cjs` は本番Chrome拡張を一時プロファイルに読み込み、合成Moodleページへの通信をすべてテスト側で応答する。ダーク設定の端末上で新規ライト表示、明示的なダーク・メニューOFFの再読込時の保持、通知権限の不在を確認した。実Moodleへの接続は行っていない。

## 実機で残る確認

次は実アカウントと実端末で確認する。ダミー検証の成功だけでは完了扱いにしない。

1. iPhone / iPad / Mac SafariとChromeで、課題・小テスト・フィルター・テーマ・履歴・コース移動が利用できること。
2. 通常更新・CSE別タブ更新・自動更新で実Moodleの内容が反映されること。通信数・所要時間・失敗を観測すること。
3. 取得中の画面移動・非表示化・再開、ログイン切れ、複数タブの排他制御。
4. iPhoneの長押しとスクロールの競合、端付近でのドラッグ、iPad分割表示、キーボード・読み上げによる並べ替えと保存。
5. PDF・提出ファイルのプレビューと、非対応形式の元リンクへの遷移。
6. 端末がダーク設定でも新規導入はライトで始まり、既存利用者のテーマと課題メニューOFFが維持されること。
7. 対応OS下限はビルド設定であり、各OSバージョンを網羅した実機確認を意味しない。

新しいモードや通知機能を追加する作業は自動的に再開しない。
