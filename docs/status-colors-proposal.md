# 状態・色分けの調査と改善案

2026年10月13日。添付4画像と共有ソースを確認。この調査時点では本体未変更。後続の依頼により「完了・合格」「行き詰まり・期限切れ」の色設定・フィルターを統合済み。完了・合格の表示名は「完了」に統一し、初期フィルターを「完了以外」に変更した。その後、直近イベントの予定IDによる照合も実装した（help-audit.md末尾参照）。以下の調査は修正前の記録で、状態分類そのものの再設計は未実施。

## 結論

問題は色の選び方よりも、1つの分類に「提出・得点」「期限」「取得・照合状況」を混ぜていること。単一の色で全組合せをMECEにする必要はない。独立した軸を設け、それぞれの意味と判定根拠を明確にする方が利用者の判断に役立つ。

## 画像から分かることと実装上の原因

| 例 | 確認できた問題 | 根拠・限界 |
| --- | --- | --- |
| 提出済みの「レポート提出」が紫 | 紫は未閲覧を意味していない | `displaybox.js` の `checkUnvisited()` は、保存情報と照合されず状態のクラスがない予定を一律に `unvisited` にする。添付画面は提出済みだが、実ページのHTMLと保存データがないため、この予定が照合されなかった具体的理由までは断定できない。 |
| 更新後も「本日の授業の要点」が紫 | 同名課題があると照合できない | `calendarEventMatches()` は日本語の予定名から名前を抽出し、保存済みの同種・同名課題のIDが1つの場合だけ一致とする。コースID・イベントIDによる識別がない。別コースに同名があれば、全件取得済みでも紫になる。画像の2件が実際に別IDかは未確認。 |
| 開始前の小テスト | 開始前という状態を分類していない | `ScrapeQuiz` は得点と受験回数で判定し、`start` を判定に使わない。画像の小テストは10/16開始で現在利用できない。期限だけでは「今取り組めるか」が分からない。 |
| 受験終了の Grammar が灰色 | 受験済みと結果不明が1つに潰れる | 得点は `#feedback h3` の「点数 / 満点」から取得。受験回数が1以上で点数が取れなければ `unknown`。受験済みである情報は取得できても、灰色では伝わらない。画像は終了した受験が確認できるが、完了ボタンだけで有効な提出結果・点数を推定しない。 |
| 緑・橙・黄・白・灰・紫が混在 | 提出状態、緊急度、情報不足の比較になっていない | `Scrape.statusAt()` は `incomplete/warning/expired` だけ期限で変換。完了・合格・不明・行き詰まりでは期限が3日以内でも橙にならない。期限と状態の表示軸が不揃い。 |
| 全予定が「残り○日」 | 何までの残り時間か区別できない | `updateEventRemaining()` は予定日時をカウントダウンに置換。小テストの受験開始の予定も受験終了の予定も同じ表示。色は課題の状態、時刻はその予定の日時で、意味が異なる。 |

## 推奨する表示モデル

| 軸 | 提出課題 | 小テスト | 表示方法 |
| --- | --- | --- | --- |
| 取り組み状況 | 未提出／下書き／提出済み／判定できない | 未受験／受験中／受験終了／判定できない | 主ラベル。課題の種類に適した語を使う。HTMLから確認できない場合は推測しない。 |
| 得点・結果 | 評定情報を出す場合は別項目 | 満点／合格点以上／合格点未満／合格点の設定不明／点数未公開・取得不能 | 小テストの主ラベルに添える。受験終了と満点を同義にしない。 |
| 利用期間 | 開始前／期間内／期限後／日付不明 | 同左 | 「開始まで3日」「締切まで2日」など目的を明示。期限後も提出可能かはMoodleの設定に依存するため断定しない。 |
| 情報の確認状況 | 未取得／取得済み／取得失敗 | 同左 | 最終取得時刻と短い文字表示。画面との照合失敗は別途「状態を対応付けできません」。未閲覧とは呼ばない。 |

取り組み状況は種類別に排他的に判定する。一方、「提出済み＋期限間近」「受験終了＋結果非公開」など別軸の組合せは許す。行き詰まりは独立した状態色にせず「合格点未満・受験回数の上限」のように事実を併記する。

### 色の方針

- カード全体は通常の背景とし、状態の短い文字ラベルと小さな色の印で示す。色だけで判断させない。
- 提出済みは緑、要対応の未提出・未受験は通常色、判定できない状態は中立色にする。期限間近は別の橙の表示、期限後は別の赤の表示にする。提出済みまで期限後という理由だけで警告しない。
- 未取得や照合できない状態に、未提出を連想させる強い背景色を付けない。開始前も通常色と「開始前」で示す。
- カスタム色は「状態」と「期限」の用途を分ける。ライト・ダークで文字の読みやすさを確認する。具体的な色値は表示構造の決定後に検討する。

これは将来の設計案。開始前・受験中・下書き・結果非公開等の細分化には、解析と保存形式の追加が必要であり、現在利用できる機能としてガイドには掲載していない。

## 修正する場合の優先順

1. 予定と課題を名前ではなく活動IDで結ぶ。自動取得の `AutoRefreshCollector` にはMoodleのカレンダー予定から活動を解決する処理があるため、IDを表示側へ橋渡しできるか検討する。同名時に名前から推測して色を付けない。
2. 「情報未取得」と「取得済みだが照合不能」を分ける。全体更新の成功は、検出した対象を取得したという意味。保存済みコースに含まれない活動、コースページから検出できない活動、新たな公開、照合不能、対象外の予定まで確認済みとは限らない。
3. 受験開始・終了と提出期限を区別して残り時間を表示する。一般の予定を一律に課題の未参照にしない。
4. 提出・受験、結果、期間を分離する。既存データの移行、状態フィルター、色設定、コース内表示、予定欄を一緒に設計する。
5. 同名課題／取得失敗／開始前／受験済み結果非公開／提出済み期限間近／期限後の各組合せを確認する。

## 既存ガイドの問題（完成稿を維持し、未修正）

- 「未参照：まだ確認していない課題」は上記の照合失敗にも付くため、本人の閲覧有無という意味では不正確。
- 「不明」は提出課題にも存在するが、説明とフィルター名「点数不明(小テストのみ)」は小テストに限定している。
- 「未提出」は小テストの受験済み・合格点未満も含む。説明の「回答していない」だけでは網羅していない。カード自身は「未完了」と表示する。
- 「合格」は合格点が取得できない場合でも、受験回数と得点があれば付くことがある。合格点に到達したと断言できない。
- 「期限近い」は色設定の名前だがカード表示は「要注意」。提出課題だけでなく未完了の小テストにも適用する。
- 「期限切れ」は期限を過ぎたすべての課題ではなく、未完了系の状態だけを変換する。
- 「完了」は手動の「完了とする」でも付く。満点・提出済みを自動確認した意味とは限らない。手動変更後に次の取得で未知以外の状態が返ると再分類される。
- 「完了以外」には小テストの合格も含まれるため、「まだ終えていない」とは必ずしも一致しない。
- フィルター「今週」は暦上の今週ではなく現在から7日以内、「進行中」は開始前も含む期限前の課題。受験可能な期間とは一致しない。

## 原因の確定に必要な確認

添付の各予定のイベントID・所属コース・活動ID、保存済み同名課題のID、全体更新の対象コースと取得エラーを実機で照合する。ユーザーの「全体更新した直後」という状況は尊重するが、画面画像だけで照合失敗の原因を1つに決めない。
