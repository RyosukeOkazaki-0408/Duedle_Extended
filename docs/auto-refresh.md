# 課題情報の自動更新

Chrome・Safari共通で、ログイン済みのMoodleを表示している間に課題情報を更新します。非表示のタブ・ログイン画面では取得しません。画面を離れたら通信を中止し、取得済みの情報と残りの作業を保存します。閉じている間に決まった時刻で動く機能ではありません。

## 更新の間隔

締切一覧は、Moodleの読み取り専用API `core_calendar_get_action_events_by_timesort` で55〜75分ごとに確認します。APIの利用可否は、名工大Moodleのログイン済みSafariで利用者が実行した診断結果（`status: ok`、最大5件）により確認しています。拡張機能としての自動更新全体は、実アカウントでの追加確認が必要です。

課題の詳細を再取得する基準は次のとおりです。

| 課題の状態 | 前回の詳細取得からの経過時間 |
| --- | --- |
| 締切まで0〜24時間の未完了課題 | 3時間 |
| その他の未完了課題（期限切れ・締切なしを含む） | 12時間 |
| 完了済み、または非表示の課題 | 24時間 |

最後に詳細を正常取得して保存した `fetchedAt` を使います。旧データにこの時刻がない場合は順次再取得します。表示・非表示の変更やレビューの単一受験点だけでは、詳細全体の取得時刻を進めません。レビュー閲覧時に正規概要を再取得できた場合は、その取得・保存で詳細の鮮度を更新します。

新規課題や一覧に変化があった課題は、この時間を待たずに詳細取得の対象にします。対象が多い場合は小分けの順番待ちになります。カレンダーイベントの `timemodified` は提出状況や成績のすべての変化を保証しないため、通常の詳細再取得も併用します。一覧から消えたことだけで完了・削除とは判定しません。

## 取得量と時刻の分散

- 初回は1〜5分待ちます。保存済みの予定時刻を大きく過ぎて再び表示した場合も、1〜5分待ちます。
- 次回時刻は端末の `storage.local` に保存します。ページの再読み込みでは待ち時間を引き直さず、端末間でも同期しません。
- 1回の処理は、一覧API最大2ページ（各最大50イベント）、コース確認最大1ページ、課題詳細最大8件です。取得は直列で、通信の間に1.5〜3秒の待ち時間を入れます。1回の処理時間にも上限を設けています。
- 続きがある場合は5〜10分後に小分けの取得を続けます。詳細取得には古い情報のための枠も確保し、新規課題が続いても既存の課題が取り残されないようにします。
- APIは直近14日〜今後90日のイベントを確認します。続きのページを取得する間は期間を固定し、イベントが多い場合でも順次取得します。
- ページ分割されたコースはセクションの続きを保存し、1回1ページずつ確認します。全セクションの確認が終わるまでコースの確認済み時刻を進めません。
- 締切のない課題などを見つけるため、画面・APIで最近確認したコースも24時間ごとに順番に確認します。過去に保存したコースIDの全履歴を自動で巡回する方式は使いません。

端末ごとにランダムな予定時刻を持つため、全員が同じ時刻に更新しにくくなります。端末同士が通信して更新枠を予約する仕組みではありません。

## 重複・失敗への対応

自動更新・手動の通常更新・CSE用の別タブ更新で共通の実行ロックを使います。複数タブが開いていても、そのブラウザでは1つだけ取得します。実行権は90秒で期限切れになり、処理中は延長します。背景ページが停止した場合も、残ったロックは回復できます。

ログイン切れ、混雑を示すHTTP 429、サーバーエラーなどでは取得を中断します。部分失敗も含め、再試行間隔を約15分、30分、60分、最大120分へ延ばします。失敗した課題を新しい情報として扱うことはありません。

手動の課題更新の3時間クールダウンは維持します。すべて成功した手動更新だけが、このクールダウンを進めます。自動更新では進めません。

## 開発・確認

- `src/storage/class/AutoRefreshCollector.js`: API照会、課題の選択、分割取得。
- `src/storage/class/RefreshCoordinator.js`: 端末内の実行ロック、予定時刻、再試行。
- `src/storage/auto_refresh.js`: 表示状態とページのライフサイクル。

`python3 scripts/check_extension.py` で共有コードの構文・manifest参照と回帰テストを確認します。実機では、一覧の変化・提出後の状態・成績の反映・複数タブ・非表示からの復帰を確認してください。

公式資料：[MoodleのAPI定義](https://github.com/moodle/moodle/blob/MOODLE_400_STABLE/lib/db/services.php)、[イベントの項目定義](https://github.com/moodle/moodle/blob/MOODLE_400_STABLE/calendar/classes/external/event_exporter_base.php)、[AJAXの通信形式](https://jsdoc.moodledev.io/4.01/lib_amd_src_ajax.js.html)。

## 一覧の表示と成功時刻

初回は課題メニューを表示し、未取得であることを説明します。課題0件やフィルター変更だけでは追加通信を開始しません。明示的なメニューOFFは保存・復元します。

「最終更新」は手動の対象コース巡回が成功し保存が終わった日時、「締切一覧確認」は自動取得の対象期間の全ページが完了し、その回の処理と保存が成功した日時です。後者は各課題詳細の鮮度を保証しません。途中ページ・中断・失敗では最後の成功日時を進めません。

過去の成功記録がない既存データでは「記録なし」と表示します。課題データを破棄して未取得扱いにはしません。時刻と取得履歴は端末内に保存し、端末間同期しません。
