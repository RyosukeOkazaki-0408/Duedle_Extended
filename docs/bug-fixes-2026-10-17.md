# Duedle 不具合修正・検証記録

2026年10月14日の[監査](bug-audit-2026-10-14.md)で確認した10件を修正し、10月15日に全体検証、10月17日に追加の互換性修正と最終検証を行った。監査対象は `30a825186e083c8866b483535482840fab939236`。修正の多くは現在の `56846c4` に含まれ、最終の日付互換性・テスト・記録の変更は作業フォルダに反映している。

## 修正内容

| 監査番号 | 修正と既存機能の保護 |
| --- | --- |
| 1 | CSE収集先のアカウント登録を待ち、取得元と保存先のアカウント・ページ識別子を保存直前に検証。識別不能・切替・古い応答では保存しない。収集タブの所有者をアカウント切替後も保持し、遅延したページが以前のアカウントへ戻すことを防ぐ。 |
| 2 | 手動取得・自動更新・CSEが同じコースの別セクションも辿る。重複・循環・別コース・別サイトを除外し、1コース最大200ページで打ち切った場合は完全成功と扱わない。自動更新は1回の処理予算を維持し、続きから取得する。 |
| 3 | レビューから概要を再取得して保存する際、読み取り後に別の更新があれば上書きを中止する。期限・受験回数・得点の巻き戻りを防ぎ、非表示設定を保持する。 |
| 4 | 単一受験の点数を総合点として保存しない。概要ページの確定した総合点を使用し、最高点・最初・最後・平均の採点方式を尊重する。取得失敗時は保存済みデータを保持する。 |
| 5 | レビュー概要表の評点行を識別し、後続のフィードバックや無関係な表の数字を点数と取り違えない。 |
| 6 | 日本語・英語の日時、合格点、受験上限を解析。設定なしと取得不能を区別し、合格点不明を合格と断定しない。入れ子の日時ブロックと従来の見出しなし表示も検証した。 |
| 7 | 他タブの更新を実際に見ていた画面に完了・中断結果を表示する。再読み込み時に過去の通知を再表示しない。 |
| 8 | 閲覧履歴の追加を背景側で直列化し、複数タブの同時追加が消えないようにした。既存の重複整理・並び順・10件の上限を保持する。 |
| 9 | テーマ変換後にページが更新した色・背景色・優先指定・削除を記録し、テーマ切替時に古い値へ戻さない。継承色と連続切替、監視処理の無限反応も検証した。 |
| 10 | 受験上限の欠損を `?`、確認できた無制限を `∞` と表示し、`undefined` の表示を防いだ。 |

監査時の追加候補だった「一時収集タブによる閲覧履歴の置換」も除外処理を追加した。収集タブの所有者情報はタブ終了時に除去し、ブラウザ再起動時には保存された旧タブ番号も無効化する。

## 検証の範囲

Chromeは実ブラウザ上の合成Moodleページを使用した。実際の大学Moodleへのログイン、課題提出、成績変更は行っていない。Safariはビルド確認であり、実機上の拡張機能動作は未検証。10月17日のXcodeログにはCoreSimulatorのバージョン不一致とAppIntentsメタデータ抽出省略の警告があるが、両ターゲットのビルドは成功した。

監査時の未確定候補「折りたたんだセクションへの直接hashリンク」は、Moodle自身の処理との組合せを実環境で確認できていないため変更していない。リリース・配布は行っていない。
